# Comparison Matrices

Comparison is a thinking aid; the choice stays with the user.

- Derive criteria from what the decision actually needs to achieve, not from what is easy to
  measure; include one or two "how it fails" criteria (support, exit cost, worst case).
- Distinguish hard constraints (must have) from soft criteria (more is better); options failing
  a hard constraint drop out before any scoring.
- A weighted matrix works well when criteria conflict: score each option per criterion, weight
  by importance to the user, and show the arithmetic so it can be challenged.
- Keep scores coarse (0–3 or 1–5); false precision hides real uncertainty.
- Record the evidence behind each cell — a link, a measurement, or a quote — so the matrix can
  be audited later.
- Include a "do nothing / status quo" column when it is a real alternative.
- Present sensitivity: which single score, if wrong, would change the recommendation.
- Say plainly when two options are close enough that preference should decide.

Adapt or skip any part; the user may legitimately weigh criteria differently than the analysis suggests.
